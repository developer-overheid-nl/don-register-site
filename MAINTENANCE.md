## 2. Where things go

| I want to add… | Put it in… | Also… |
| :-- | :-- | :-- |
| A generic React component | `packages/components/src/<name>/<Name>.tsx` | Add `<Name>.stories.tsx` (see Storybook conventions in AGENTS.md), export it from `src/index.ts`, add a changeset |
| A component used by one app only | `apps/<app>/src/components/` (+ `*.module.css`) | Promote it to `packages/components` once a second app needs it |
| A page shell / layout | `packages/layouts/src/don/` | Export it from `packages/layouts/src/index.ts`, add a changeset |
| A pure helper shared by apps | `packages/layouts/src/helpers/` | Colocated `*.test.ts`, export from `helpers/index.ts`, add a changeset |
| A helper for one app | `apps/<app>/src/helpers/` or next to the component that uses it | Colocated `*.test.ts` |
| A UI string | `packages/locales/nl/translation.json` | Add a changeset |
| An app-specific string override | `i18n` in `apps/<app>/app.config.ts` | — |
| Title, meta, navigation, footer, item labels | `apps/<app>/app.config.ts` | — |
| A route | `apps/<app>/src/pages/` | Follow the routing pattern in AGENTS.md (`pagina/[...page]`, `[id]`) |
| A static content page | `apps/<app>/src/pages/*.md` | Front-matter per [apps/api-register/README.md](apps/api-register/README.md) |
| A form submission / mutation | `apps/<app>/src/actions/index.ts` (Astro Actions) | Not an API route |
| A server env var or secret | `env.schema` in `apps/<app>/astro.config.mjs` | Add it to `.env.mode.example`; if CI needs it, add the secret to `build.yml` and list it in [§6](#6-deploying) |
| Logos, fonts, icons with copyright | `proprietary-don/` | Add a royalty-free equivalent to `proprietary-example/` with the same export names |
| Static files for one app | `apps/<app>/public/` | — |
| An end-to-end test | `cypress/e2e/<app>/*.cy.ts` | — |
| An OpenAPI backend | `redocly.yaml` | Run `pnpm generate:oas:types` |

**Rule:** code in `packages/*` must not assume a specific app. The [register-site-template](https://github.com/developer-overheid-nl/register-site-template) consumes these packages as-is.

**Rule:** import `@developer-overheid-nl/proprietary`, never `proprietary-don` or `proprietary-example` directly.

## 3. Generated files: never edit by hand

| File(s) | Regenerate with |
| :-- | :-- |
| `apps/*/src/types/*-schema.prod.ts`, `*-schema.test.ts` | `pnpm generate:oas:types` |
| `*/CHANGELOG.md` (not the root index) | Changesets (`publish.yml` / `pnpm changesets:version`) |
| `.astro/`, `dist/`, `storybook-static/` | Build output, git-ignored |

Hand-written files next to the generated types:

- `api-schema.ts` (all apps) and `tools-schema.ts` (api-register): switchers between `.prod` and `.test`. On `main`, every switcher must export from `.prod`.
- `unknown-schema.ts` (api-register): a fallback type for when no OAS is configured.

`noTestSchemas.grit` warns when a switcher points at `.test`, and CI fails pull requests on that warning.

## 4. Update procedures

### Monthly package update

1. Create an issue, then a branch named `<issue>-package-updates-<month>-<year>` (e.g. `356-package-updates-oktober-2026`).
2. Merge open Dependabot PRs (`.github/dependabot.yml`, weekly) into this branch, or close them if the branch supersedes them.
3. Bump versions in `pnpm-workspace.yaml`: `catalog:` (shared runtime deps) and `catalogs.react19` (peer/dev deps of `packages/components` and `packages/layouts`).
4. Bump the pinned devDependencies in the root `package.json` (Biome, Changesets, Storybook, Cypress, Playwright, lefthook, …).
5. Check each entry under `overrides:` in `pnpm-workspace.yaml`. Remove it if the upstream fix has landed.
6. Run `pnpm install`, then the [verify set](#8-before-you-open-a-pull-request).
7. Add a changeset for every package whose dependencies changed.

### Major upgrades (Astro, RHC, Storybook, Biome, React)

Do each one on its own branch, never inside the monthly update.

- **Astro:** bump `astro` and all `@astrojs/*` in `catalog:` together. Read the upgrade guide; check `astro.config.mjs` in all three apps and the root.
- **RHC** (`@rijkshuisstijl-community/*`, `@utrecht/*`): bump the catalog entries, then check Chromatic for visual changes. A visual breaking change means a major changeset for `packages/components` / `packages/layouts`.
- **Storybook:** bump all `storybook` / `@storybook/*` versions in the root `package.json` together; run `pnpm test:storybook`.
- **Biome:** bump `@biomejs/biome`, run `pnpm biome:migrate`, then `pnpm biome:check`.
- **React:** keep `catalog:` and `catalogs.react19` consistent with `overrides.react` / `overrides.react-dom`.

### Node.js version

Update these together:

1. `.node-version` (UTF-8, no BOM)
2. `engines.node` in the root `package.json`
3. `node-version:` in `.github/workflows/*.yml`
4. The base images in `Dockerfile` (`node:lts`, `node:lts-alpine`) if the LTS line changes

### Backend API changed

1. Run `pnpm generate:oas:types`.
2. Run `pnpm test:ts` and fix the type errors.
3. To develop against the test backend, point the switcher (`api-schema.ts`) at `.test` temporarily. Point it back at `.prod` before merging.

### Adding a new app

Every place that lists the apps by name:

1. `apps/<app>/` with `package.json`, `astro.config.mjs`, `app.config.ts`, `biome.json`, `vitest.config.ts`, `.env.mode.example`
2. Root `package.json`: `dev:`, `build:`, `preview:`, `start:` scripts (`scripts/start.mjs` groups them automatically by `action:app`)
3. `redocly.yaml` (prod + test) and `src/types/api-schema.ts`
4. `Dockerfile`: a `runtime-<app>` target
5. `.github/workflows/`: `build.yml`, `deploy-test.yml`, `deploy-prod.yml`, plus a `KUSTOMIZE_PATH_<APP>` repository variable
6. `cypress/e2e/<app>/` and a `test:e2e:<app>` script
7. Docs: README (Apps section), the root [CHANGELOG.md](CHANGELOG.md) index, [publiccode.yml](publiccode.yml), [AGENTS.md](AGENTS.md)

## 5. Versioning and releasing

Versioning uses [Changesets](https://github.com/changesets/changesets) and [SemVer](https://semver.org/). A possible visual breaking change also counts as a major.

**When to add a changeset** (`pnpm changeset`, see [.changeset/README.md](.changeset/README.md)):

- Always for changes in `packages/*` or `proprietary-*`.
- For app changes you want in the app's changelog.
- Not for root-only changes (docs, CI, root config).

**Published to npm (public):**

- `@developer-overheid-nl/don-register-components`
- `@developer-overheid-nl/don-register-layouts`
- `@developer-overheid-nl/don-register-locales`
- `@developer-overheid-nl/proprietary-example`

**Private, versioned and changelogged only:** the three apps, `proprietary-don`, and the root package.

**Release flow** (`.github/workflows/publish.yml`):

1. A merge to `main` with pending changesets opens or updates the "Version Packages" PR (branch `changeset-release/main`).
2. Review the version bumps and changelogs in that PR, then merge it.
3. The workflow builds and publishes the public packages to npm (trusted publishing via OIDC).

Canary releases: `pnpm changesets:version:canary` and `pnpm changesets:publish:canary`.

## 6. Deploying

Deploys go through GitHub Actions and a separate infra repository. This repo never deploys directly.
Three images are built: `ghcr.io/developer-overheid-nl/don-register-site` (api), `don-register-oss-site` and `don-register-schema-site`.

### Variables and secrets

| Name | Type | Used by |
| :-- | :-- | :-- |
| `INFRA_REPO` | Organization variable, e.g. `developer-overheid-nl/don-infra` | deploy-test, deploy-prod |
| `KUSTOMIZE_PATH_API`, `KUSTOMIZE_PATH_OSS`, `KUSTOMIZE_PATH_SCHEMA` | Repository variables, base path e.g. `apps/oss/overlays/` | deploy-test, deploy-prod |
| `RELEASE_PROCES_APP_ID`, `RELEASE_PROCES_APP_PRIVATE_KEY` | Secrets: GitHub App that writes to the infra repo | deploy-test, deploy-prod |
| `CHANGELOG_APP_CLIENT_ID` (variable), `CHANGELOG_APP_PRIVATE_KEY` (secret) | GitHub App that opens the "Version Packages" PR | publish |
| `API_X_API_KEY`, `PIWIK_PRO_SITE_ID` | Secrets written to `.env.production.local` for the CI build | build |
| `CHROMATIC_PROJECT_TOKEN` | Secret | chromatic |

### Deploy to test

`.github/workflows/deploy-test.yml` runs on pushes to any branch except `main`.

1. Check the schema switchers: point them at `.test` if the test environment needs the test backend (see [§3](#3-generated-files-never-edit-by-hand)).
2. Put `[deploy-test]` in the commit message, e.g. `feat: pas content aan [deploy-test]`. Commits without it are not deployed.
3. The workflow pushes the three images tagged `test` and the commit SHA, then commits the new tags to `${KUSTOMIZE_PATH_<APP>}test/kustomization.yaml` in `INFRA_REPO`.
4. Before merging to `main`, point the switchers back at `.prod`.

### Deploy to production

`.github/workflows/deploy-prod.yml` runs on every push to `main`.

1. The workflow pushes the three images tagged `latest` and the commit SHA.
2. It opens a pull request in `INFRA_REPO` that updates `${KUSTOMIZE_PATH_<APP>}prod/kustomization.yaml` for all three apps.
3. Merging that pull request rolls out production.

### Other automated workflows

| Workflow | Trigger | Does |
| :-- | :-- | :-- |
| `build.yml` | every push | Unit tests, build, Cypress (api + oss), Docker images |
| `pull_request.yml` | push, PR | `biome ci` (`--error-on-warnings` on PRs) |
| `json-ci.yml` | PR | JSON and OpenAPI validation (Super-Linter) |
| `chromatic.yml` | push | Visual tests of Storybook |
| `deploy-github-pages.yml` | push to `main` | Publishes Storybook to GitHub Pages |
| `publish.yml` | push to `main` | Changesets release (see [§5](#5-versioning-and-releasing)) |

## 7. Keeping docs current

Update the owning doc in the same pull request as the change.

| When you change… | Update… |
| :-- | :-- |
| A root `package.json` script | Commands in [AGENTS.md](AGENTS.md) |
| Architecture, routing, or a shared component boundary | [AGENTS.md](AGENTS.md) |
| A Storybook convention or tag | Storybook conventions in [AGENTS.md](AGENTS.md) |
| A workflow, CI variable or secret | [§6](#6-deploying) of this file |
| Where a kind of file lives | [§2](#2-where-things-go) of this file |
| Package or app list | [README.md](README.md), the root [CHANGELOG.md](CHANGELOG.md), [publiccode.yml](publiccode.yml), [§4 Adding a new app](#adding-a-new-app) |
| Public API of a published package | That package's `README.md` + a changeset |

**For agents:** treat a doc that disagrees with the code as a bug. Fix the doc in the same change, or report it if fixing is out of scope.

## 8. Before you open a pull request

1. `pnpm biome:check`
2. `pnpm test:ts`
3. `pnpm test -- run`
4. `pnpm test:storybook` (if `packages/components` changed)
5. `pnpm build`
6. A changeset is added if `packages/*` or `proprietary-*` changed
7. Every schema switcher (`api-schema.ts`, `tools-schema.ts`) exports from `.prod`
